# Contributing to Nabira

Спасибо, что хотите помочь Nabira. Полезны не только pull request: воспроизводимый баг-репорт,
пример ложного исправления и проверка на другом приложении или языке тоже двигают проект вперёд.

## Перед созданием issue

1. Проверьте, нет ли уже похожего issue.
2. Укажите macOS или Windows, версию Nabira и приложение, в котором возникла проблема.
3. Приложите безопасный пример: что было введено, что получилось и какой результат ожидался.
4. Не публикуйте пароли, токены, приватную переписку и другие чувствительные данные.

Для проблем безопасности используйте инструкции из [SECURITY.md](SECURITY.md), а не публичный issue.

## Изменения кода

1. Создайте отдельную ветку от актуальной `main`.
2. Сведите изменение к одной понятной задаче и добавьте регрессионный тест.
3. Запустите проверки нужной платформы.
4. Опишите в pull request проблему, решение и способ ручной проверки.

### macOS

```bash
cd macos
swift test
```

### Windows

```powershell
dotnet test windows/tests/Nabira.Win.Tests/Nabira.Win.Tests.csproj -c Release
```

Реальную работу глобального перехвата клавиатуры нужно дополнительно проверять на соответствующей
операционной системе. Сборка Windows на macOS или Linux подтверждает компиляцию, но не поведение
системного ввода.

## Язык и стиль

- Пользовательский интерфейс должен оставаться понятным на русском языке.
- Новое поведение macOS и Windows по возможности должно совпадать.
- Автоматические исправления проектируются по принципу precision-first: сомнительный текст лучше
  оставить без изменения, чем уверенно испортить.
- Обработка набранного текста должна оставаться локальной.
